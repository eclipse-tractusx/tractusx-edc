    Why Tractus-X EDC?¶

    Eclipse Dataspace Components (EDC) is a framework: a set of modules and extension points from which you assemble your own connector. It implements the Dataspace Protocol (DSP) and the Decentralized Claims Protocol (DCP), but it leaves the runtime, the packaging, the dataspace rules and the operations to you.

    Tractus-X EDC is that connector, ready to run. It is built on a pinned EDC version and adds the extensions, the release artefacts, the tests and the community that a company needs to join a dataspace and to stay in it across releases: Catena-X out of the box, and Manufacturing-X dataspaces such as Factory-X and Construct-X, or any other dataspace that speaks the Dataspace Protocol (DSP) and uses the Decentralized Claims Protocol (DCP) for authorization, through dataspace extensions.

    • Ready to run

      Released control plane, data plane and in-memory runtimes, as OSS images on Docker Hub: multi-architecture, non-root, for every release.

      Docker Sponsored OSS

    • Helm charts

      The tractusx-connector chart (production, with optional PostgreSQL and Vault) and tractusx-connector-memory (testing), published to the Tractus-X Helm repository and tested on every CI run.

      Deploy in five minutes

    • Catena-X rules built in

      The Catena-X policy constraints (CX-0152), Business Partner Number and BPN group checks, the BPN-DID Resolution Service (BDRS) client and the Catena-X credential scopes.

      Catena-X policies

    • Extensible for your dataspace

      A dataspace-agnostic core: the rules of Factory-X, Construct-X or your own dataspace are added as extensions, the way the Catena-X rules are.

      Supported dataspaces

    • Any DCP wallet

      Works with the open-source Tractus-X Identity Hub, SAP's managed DIV, or any wallet that implements DCP.

      Wallets you can use

    • Production-ready

      Released for production and running in production in Catena-X. As with any open-source software, you run it at your own risk (Apache License 2.0, no warranty).

      Production checklist

    • A mature release cycle, an open roadmap

      A release every quarter, aligned with Eclipse Tractus-X: release candidates tested before the final release, and bugfix releases that contain only the fix. The roadmap is planned in public, so any company can see what comes next, propose features and contribute.

      Release planning board

    • An open community

      Developed in the open in Eclipse Tractus-X, with a regular, public Connector Open Meeting where anyone can ask questions.

      Get help

    What you get on top of upstream EDC¶

    Upstream EDC on its own Tractus-X EDC
    Runtime Assemble your own from modules Released runtimes: control plane, data plane and in-memory
    Container images Build and host your own OSS images on Docker Hub for every release, multi-architecture, non-root
    Kubernetes Write your own manifests Helm charts with PostgreSQL and Vault options and built-in helm test checks
    Catena-X policies Write your own policy functions CX-0152 constraints, BPN and BPN group checks, contract definition validation
    Identity Generic DCP Tested with the Tractus-X Identity Hub and SAP DIV; in Catena-X the BDRS client (BPN ↔ DID) and credential scopes; presentation cache
    Other dataspaces Assemble from modules A dataspace-agnostic core and dataspace extensions; Factory-X and Construct-X build on it
    Protocol versions The current DSP version DSP 2025-1 and DSP 0.8 side by side, with connector discovery, so partners on older releases stay reachable
    Data access EDR building blocks The /v3/edrs API, automatic transfer after negotiation and token refresh
    Agreements Agreements end with their policy Agreement retirement and the BPNs of both parties stored with each agreement
    Releases Follow the upstream releases A quarterly release aligned with Eclipse Tractus-X, release candidates tested by QA, pure bugfix releases for the release in use, GitHub milestones
    Roadmap The upstream project's plans Open planning: features are proposed as issues and planned in public sessions and on the release planning board (how it works)
    Upgrades Follow upstream release notes Flyway database migrations, a migration guide per release and an upgradeability test in CI
    Quality and compliance Your own pipeline Deployment, end-to-end and upgradeability tests, CodeQL, Trivy, KICS and secret scans, Eclipse license checks of every dependency
    Help The EDC community The Connector Open Meeting, a Matrix room, GitHub Discussions, this documentation, the Connector KIT and the Connector Sensei

    Not either-or

    Tractus-X EDC is EDC: every upstream extension point still works, and you can add your own extensions to the Tractus-X runtimes. See Tutorial 4: your first extension. Fixes and features that are not dataspace specific are meant to go upstream.

    When upstream EDC alone is the better fit¶

    • You want to assemble every module yourself. For a dataspace with different rules than Catena-X, consider a dataspace extension on Tractus-X EDC first.
    • You work on EDC itself, or on a feature that belongs upstream.

    Everyone else, in Catena-X and in other dataspaces, saves time with the released runtimes, images and charts of Tractus-X EDC.
