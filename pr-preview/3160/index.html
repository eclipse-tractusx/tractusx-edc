    Eclipse Tractus-X · Dataspace connector

    Tractus-X EDC¶

    The open-source, production-ready dataspace connector. Tractus-X EDC packages the Eclipse Dataspace Components (EDC) with the extensions, policies and identity integration a company needs to share data in a sovereign and secure way: in Catena-X, in Manufacturing-X dataspaces such as Factory-X and Construct-X, and in any other dataspace that speaks the Dataspace Protocol (DSP) and uses the Decentralized Claims Protocol (DCP) for authorization. Every part is an extension, so you can add the rules of your own dataspace.

    Install¶

    helm repo add tractusx-edc https://eclipse-tractusx.github.io/charts/dev
helm repo update
helm search repo tractusx-edc/tractusx-connector -l   # released chart versions

helm install my-connector tractusx-edc/tractusx-connector --version <chart-version> -f my-values.yaml

    No values file yet? Deploy in five minutes has copy-paste values for a local try-out, with PostgreSQL and Vault or fully in memory.

    cat > compose.yaml <<'EOF'
# Tractus-X EDC in memory (control plane and data plane in one container): for a local try-out only,
# every restart forgets all assets, policies and contracts. The identity values are placeholders.
services:
  edc:
    image: tractusx/edc-runtime-memory:0.13.0
    ports:
      - "8080:8080"   # health checks: /api/check/readiness
      - "8081:8081"   # Management API
      - "8084:8084"   # Dataspace Protocol
      - "8086:8086"   # data plane public API
    environment:
      OTEL_JAVAAGENT_ENABLED: "false"
      EDC_PARTICIPANT_ID: did:web:changeme
      EDC_IAM_ISSUER_ID: did:web:changeme
      EDC_PARTICIPANT_CONTEXT_ID: try-participant-context
      TRACTUSX_EDC_PARTICIPANT_BPN: BPNL000000000001
      WEB_HTTP_PORT: "8080"
      WEB_HTTP_PATH: /api
      WEB_HTTP_MANAGEMENT_PORT: "8081"
      WEB_HTTP_MANAGEMENT_PATH: /management
      WEB_HTTP_MANAGEMENT_AUTH_TYPE: tokenbased
      WEB_HTTP_MANAGEMENT_AUTH_KEY: password
      WEB_HTTP_CONTROL_PORT: "8083"
      WEB_HTTP_CONTROL_PATH: /control
      WEB_HTTP_PROTOCOL_PORT: "8084"
      WEB_HTTP_PROTOCOL_PATH: /api/v1/dsp
      WEB_HTTP_PUBLIC_PORT: "8086"
      WEB_HTTP_PUBLIC_PATH: /api/public
      EDC_DSP_CALLBACK_ADDRESS: http://edc:8084/api/v1/dsp
      EDC_DATAPLANE_API_PUBLIC_BASEURL: http://localhost:8086/api/public
      TX_EDC_DATAPLANE_TOKEN_REFRESH_ENDPOINT: http://localhost:8086/api/public/token
      EDC_TRANSFER_PROXY_TOKEN_SIGNER_PRIVATEKEY_ALIAS: key-1
      EDC_TRANSFER_PROXY_TOKEN_VERIFIER_PUBLICKEY_ALIAS: key-1
      EDC_IAM_STS_OAUTH_TOKEN_URL: https://div.example.org/oauth/token
      EDC_IAM_STS_OAUTH_CLIENT_ID: try-client-id
      EDC_IAM_STS_OAUTH_CLIENT_SECRET_ALIAS: try-client-secret
      TX_EDC_IAM_STS_DIV_URL: https://div.example.org
      TX_EDC_IAM_DCP_BDRS_SERVER_URL: https://bdrs.example.org
EOF

docker compose up -d
curl -s -X POST http://localhost:8081/management/v3/assets/request \
  -H "X-Api-Key: password" -H "Content-Type: application/json" \
  -d '{"@context": {"@vocab": "https://w3id.org/edc/v0.0.1/ns/"}, "@type": "QuerySpec"}'

    The same settings the tractusx-connector-memory chart sets; see Configuration for the rest. To exchange data with a partner, the connector needs a real wallet: see the next tab. For a generated Compose setup with a provider and a consumer, try the Tractus-X Starter Kit.

    git clone https://github.com/eclipse-tractusx/tractus-x-umbrella.git
cd tractus-x-umbrella/charts/umbrella
helm dependency update
helm install -f values-adopter-decentralized-identityhub.yaml umbrella . --namespace umbrella --create-namespace

    The Tractus-X Umbrella runs a whole dataspace on your own cluster: a provider and a consumer Tractus-X EDC, each with its own Tractus-X Identity Hub as wallet, an IssuerService and the BDRS. Start with its guide for this setup (cluster prerequisites for Linux, macOS and Windows are linked there).

    docker pull tractusx/edc-controlplane-postgresql-hashicorp-vault:<version>
docker pull tractusx/edc-dataplane-hashicorp-vault:<version>
docker pull tractusx/edc-runtime-memory:<version>     # testing only

    Multi-architecture (linux/amd64, linux/arm64), non-root, published on Docker Hub for every release. Settings come from environment variables; see Configuration.

    git clone https://github.com/eclipse-tractusx/tractusx-edc.git
cd tractusx-edc
./gradlew build          # compile, unit tests, Checkstyle (JDK 21)
./gradlew dockerize      # local images of every runtime

    Then follow Developer setup or the local quick start.

    Why Tractus-X EDC?¶

    Upstream EDC is a framework you assemble a connector from. Tractus-X EDC is that connector, ready to run in Catena-X, Manufacturing-X and other dataspaces:

    • Released runtimes and OSS images on Docker Hub, for every release
    • Helm charts with PostgreSQL and Vault options, tested on every CI run
    • Catena-X policies, BPN groups and BDRS built in, and room for your own
    • Extensible: add the policies and services of your dataspace as extensions
    • Any DCP wallet: Tractus-X Identity Hub, SAP DIV or your own
    • A mature release cycle: quarterly releases with release candidates and backported fixes, aligned with Eclipse Tractus-X
    • An open roadmap: companies join the public planning and contribute to it
    • Migrations and upgrade guides for every release, upgradeability tested in CI
    • Security scans and Eclipse license checks of every dependency
    • An open community with a public Connector Open Meeting
    • Production-ready and running in Catena-X today

    The control plane negotiates whether data may flow: it publishes offers, checks policies against verifiable credentials and records contracts. The data plane moves the data once a contract exists. Neither company hands its data to a central platform. Learn more

    Part of the Connector KIT¶

    Eclipse Tractus-X Connector KIT

    The Connector KIT describes the basic infrastructure for cross-enterprise data exchange in a dataspace: the Dataspace Protocol, identities and credentials, policies and asset design. Tractus-X EDC is its reference implementation: production-ready, in use throughout the Catena-X dataspace, and reused by other dataspaces such as Construct-X.
