# Migration Guide `0.12.x -> 0.13.x`

This document outlines the necessary changes for migrating your tractusx-edc installation from versions 0.12.x to 0.13.x.
It also outlines some points that adopters and operators should pay close attention to when migrating from one version
to another.

This document is not a comprehensive feature list.

## 1. Federate Catalog removal

The Federate Catalog feature has not been proven to be usable, that's why it will be removed. The deletion of the table 
`edc_federated_catalog` will be done automatically by migration script. If you need to keep the data, please make sure 
that `tx.edc.postgresql.migration.federatedcatalog.enabled` is set to `false` before the migration.

Along with the feature, the Helm values `controlplane.catalog.*` and `controlplane.endpoints.catalog.*` and the
corresponding `EDC_CATALOG_CACHE_*`, `TX_EDC_CATALOG_NODE_LIST_FILE` and `WEB_HTTP_CATALOG_*` settings have been
removed and must be deleted from your configuration.

## 2. Deprecated instances
API changes:

| Old API                       | New API                       |
|-------------------------------|-------------------------------|
| `/business-partner-groups`    | `/v3/business-partner-groups` |
| `/v2/edrs`                    | `/v3/edrs`                    |
| `/v4alpha/connectordiscovery` | `/v3/connectordiscovery`      |
| `/v4alpha/dataflows`          | `/v3/dataflows`               |

The endpoints previously available under `v4alpha` have been provided under management API `v3` as well. The `v4alpha`
variants are still served, but are marked as deprecated since 0.13.0. Switching to the `v3` paths is therefore not
required for this upgrade, but it is recommended, as the `v4alpha` variants will be removed in a future release.

Additionally, several configuration parameters deprecated since version 0.8.x have also been removed.
Please use the updated configuration parameters instead.

[SqlBusinessPartnerGroupStoreExtension](../../edc-extensions/bpn-validation/business-partner-store-sql/src/main/java/org/eclipse/tractusx/edc/validation/businesspartner/store/SqlBusinessPartnerGroupStoreExtension.java):

| Old value                 | New value                      | New environment variable       |
|---------------------------|--------------------------------|--------------------------------|
| `edc.datasource.bpn.name` | `edc.sql.store.bpn.datasource` | `EDC_SQL_STORE_BPN_DATASOURCE` |


[SqlEdrLockExtension](../../edc-extensions/edr/edr-index-lock-sql/src/main/java/org/eclipse/tractusx/edc/edr/index/sql/lock/SqlEdrLockExtension.java):

| Old value                 | New value                      | New environment variable       |
|---------------------------|--------------------------------|--------------------------------|
| `edc.datasource.edr.name` | `edc.sql.store.edr.datasource` | `EDC_SQL_STORE_EDR_DATASOURCE` |

## 3. Postgres Version

The new version provides Postgres version 18.0 as dependency in the helm charts referring to the Cloud Pirates
helm charts and the official Postgres docker image instead of the formerly used bitnami charts and docker images.

As a consequence, for a Kubernetes setup done with the provided helm charts, there is no possibility to do an automatic
upgrade with the provided helm charts, as the two images are not supporting that. Instead, during update, an operator
has to follow the general
[migration guide](https://github.com/eclipse-tractusx/tutorial-resources/blob/main/migration-guides/GENERIC_POSTGRESQL_MIGRATION_GUIDE.md#:~:text=GENERIC_BITNAMI_TO_CLOUDPIRATES_KEYCLOAK_MIGRATION_GUIDE.md-,GENERIC_POSTGRESQL_MIGRATION_GUIDE,-.md)

Further, the chart now differentiates between admin and custom user. It is recommended to use a custom user. Please
follow the [database configuration section](../../charts/tractusx-connector/README.md#database-configuration) of the helm documentation of the tractusx-connector.

## 4. Participant identity configuration

The meaning of the Helm value `participant.id` has changed. It now carries the **DID** of the connector (the value that
was previously configured under `iatp.id`), while the BPNL moved to the new value `participant.bpnl`.

| Old Helm value   | New Helm value     | Content                       |
|------------------|--------------------|-------------------------------|
| `iatp.id`        | `participant.id`   | DID, e.g. `did:web:changeme`  |
| `participant.id` | `participant.bpnl` | BPNL, e.g. `BPNL0000000000XX` |

This maps to the runtime configuration as follows:

| Environment variable            | Setting                        | Content                       |
|---------------------------------|--------------------------------|-------------------------------|
| `EDC_PARTICIPANT_ID`            | `edc.participant.id`           | DID of the connector          |
| `EDC_IAM_ISSUER_ID`             | `edc.iam.issuer.id`            | DID of the connector          |
| `TRACTUSX_EDC_PARTICIPANT_BPN`  | `tractusx.edc.participant.bpn` | BPNL of the connector         |
| `EDC_PARTICIPANT_CONTEXT_ID`    | `edc.participant.context.id`   | Participant context id (UUID) |

> [!IMPORTANT]
> `edc.participant.context.id` remains a mandatory setting and must never change once set. It is now also used to derive
> the DID document service id, see [section 7](#7-did-document-service-self-registration).

## 5. `IATP` renamed to `DCP`

The former "IATP" naming has been consistently replaced by "DCP" (Decentralized Claims Protocol). This affects the Helm
values, the runtime settings and the module coordinates.

Helm values: the whole `iatp` block has been renamed to `dcp` (`iatp.trustedIssuers` -> `dcp.trustedIssuers`,
`iatp.cache.*` -> `dcp.cache.*`, `iatp.didService.*` -> `dcp.didService.*`, `iatp.sts.*` -> `dcp.sts.*`).

Runtime settings:

| Old setting                             | New setting                            | New environment variable               |
|-----------------------------------------|----------------------------------------|----------------------------------------|
| `tx.edc.iam.iatp.bdrs.server.url`       | `tx.edc.iam.dcp.bdrs.server.url`       | `TX_EDC_IAM_DCP_BDRS_SERVER_URL`       |
| `tx.edc.iam.iatp.bdrs.cache.validity`   | `tx.edc.iam.dcp.bdrs.cache.validity`   | `TX_EDC_IAM_DCP_BDRS_CACHE_VALIDITY`   |
| `tx.edc.iam.iatp.credentialservice.url` | `tx.edc.iam.dcp.credentialservice.url` | `TX_EDC_IAM_DCP_CREDENTIALSERVICE_URL` |
| `tx.edc.iam.iatp.default-scopes.*`      | `tx.edc.iam.dcp.default-scopes.*`      | `TX_EDC_IAM_DCP_DEFAULT_SCOPES_*`      |

Module coordinates (only relevant for adopters assembling their own runtimes): the `tx-dcp` extension has been split
into `edc-extensions:dcp:tx-dcp` (protocol-agnostic parts) and `edc-extensions:dcp:cx-dcp` (Catena-X specific default
scopes and scope extractors). Both are part of `edc-controlplane-base`, so operators using the published images or Helm
charts are not affected. Java packages were renamed from `org.eclipse.tractusx.edc.iam.iatp` to
`org.eclipse.tractusx.edc.iam.dcp` accordingly.

## 6. `DIM` renamed to `DIV`

The Decentralized Identity Management (`DIM`) naming has been replaced by Decentralized Identity Verification (`DIV`).

Helm values:

| Old Helm value                        | New Helm value                       |
|---------------------------------------|--------------------------------------|
| `iatp.sts.dim.url`                    | `dcp.sts.div.url`                    |
| `iatp.sts.oauth.token_url`            | `dcp.sts.oauth.token_url`            |
| `iatp.sts.oauth.client.id`            | `dcp.sts.oauth.client.id`            |
| `iatp.sts.oauth.client.secret_alias`  | `dcp.sts.oauth.client.secret_alias`  |

Runtime settings:

| Old setting              | New setting              | New environment variable |
|--------------------------|--------------------------|--------------------------|
| `tx.edc.iam.sts.dim.url` | `tx.edc.iam.sts.div.url` | `TX_EDC_IAM_STS_DIV_URL` |

The corresponding modules were renamed as well: `edc-extensions:dcp:tx-dcp-sts-dim` ->
`edc-extensions:dcp:tx-dcp-sts-div` and `edc-extensions:did-document:did-document-service-dim` ->
`edc-extensions:did-document:did-document-service-div`.

## 7. DID document service self-registration

The setting `tx.edc.did.service.self.registration.id` (Helm value `iatp.didService.selfRegistration.id`, environment
variable `TX_EDC_DID_SERVICE_SELF_REGISTRATION_ID`) has been **removed**. The service id used for registering /
unregistering the connector's data service entry in the DID document is now derived from the participant context id as
`urn:<edc.participant.context.id>`.

> [!WARNING]
> If self-registration was enabled in 0.12.x with an explicitly configured id, the previously registered service entry
> will no longer be found under the new id. Remove the stale entry from the DID document manually (or unregister it
> before upgrading) to avoid a duplicated data service entry.

`tx.edc.did.service.self.registration.enabled` and `tx.edc.did.service.self.deregistration.enabled` (Helm:
`dcp.didService.selfRegistration.enabled`) are unchanged.

## 8. New optional Kafka data flow extension

A Kafka broker extension with OAuth2 integration for data flows has been added
(`edc-extensions:dataplane:kafka:kafka-broker-extension`, `data-address-kafka`, `validator-data-address-kafka`). It is
**not** part of the published data plane images and has to be added explicitly to a custom runtime. When enabled, it
supports broker-level access revocation via Kafka ACLs, configured through:

| Setting                                     | Default     | Description                                                           |
|---------------------------------------------|-------------|-----------------------------------------------------------------------|
| `edc.dataplane.kafka.acl.enabled`           | `false`     | Enable Kafka ACL management for immediate broker-level revocation      |
| `edc.dataplane.kafka.acl.bootstrap.servers` | -           | Bootstrap servers of the ACL admin client (required when ACL enabled)  |
| `edc.dataplane.kafka.acl.security.protocol` | `PLAINTEXT` | Security protocol of the ACL admin client                             |
| `edc.dataplane.kafka.acl.sasl.mechanism`    | -           | SASL mechanism of the ACL admin client (e.g. `OAUTHBEARER`, `PLAIN`)   |
| `edc.dataplane.kafka.acl.sasl.jaas.config`  | -           | SASL JAAS config of the ACL admin client                              |

See the [extension README](../../edc-extensions/dataplane/kafka/kafka-broker-extension/README.md) for details.
